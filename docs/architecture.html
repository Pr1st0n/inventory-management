05 — Context

Characteristics & current gaps

What defines this system as a demo, and where the working branch is mid-flight.

Demo characteristics

  • Data lives in process memory and resets on every restart — no writes are persisted.
  • CORS is fully open (allow_origins=["*"]) and auth is mocked — local use only.
  • All 14 endpoints are read-only GET; there is no create/update path on the server.
  • Views fetch broad data and derive narrow via computed props; charts are hand-drawn SVG.
  • Global filters map Location→warehouse and Period→month before hitting the API.

Current gaps — new_features

  • api.js defines /tasks & /purchase-orders calls with no matching backend routes yet.
  • Dashboard.vue references a PurchaseOrderModal component that does not exist.
  • Reports.vue bypasses api.js, calls axios directly, and uses the Options API.
  • Backlog.vue exists but is not registered in the router — surfaced inline on the Dashboard instead.
  • purchase_orders.json is empty, so backlog has_purchase_order is always false.
